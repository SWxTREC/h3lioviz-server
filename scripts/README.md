# Generating H3lioviz Compatible Runs Without Lambda
| Instructions | Commands | Example |
|---|---|---|
|Enter the scripts/ directory|`cd scripts` |
|Create a Python3.12 environment to install dependencies (works with 3.9 as well)|`python3.12 -m venv venv`|
|Activate the Python environment|`source venv/bin/activate`|
|Install needed dependencies|`pip3 install -r requirements.txt`|
|Process the data by calling `process_output.py` with the path to the directory which contains all the data files. **If you are processing SWPC data** (a run whose `project` attribute starts with `a8b1`) the final directory must match the following regex for run_id to be correctly identified as run_id is identified from the path. Otherwise the first 8 hex characters of a SHA-256 hash of the metadata will be used for the run_id. Regex for SWPC `^.*wsa_enlil_\d{5}\.\d*\.dbqs0`. **Note that the downsampling is configured by default** (8x radius, 2x latitude, and 2x longitude downsample) and you do not need to pass any flags. If you would like to create custom downsamples, you can run `python3 process_output.py -h` to find the appropriate flags.|`python3 process_output.py <path_to_nc_files>`|`python3 process_output.py ~/wsa_enlil_57671.77346046.dbqs01/`|
|Verify the processing was successful by looking for <path_to_nc_files>/pv-ready-data-<run_id>||`ls ~/wsa_enlil_57671.77346046.dbqs01/pv-ready-data-57671/`|
|Upload the run data to the appropriate s3 path. The example uses the aws CLI, but quicker copies of large number of files can be achieved with an open source tool called [s5cmd](https://github.com/peak/s5cmd) which parallelizes uploads.|`aws s3 sync <path_to_nc_files>/pv-ready-data-<run_id>/ s3://h3lioviz.<domain>/data/h3lioviz/pv-ready-data-<run_id>`|`aws s3 sync ~/wsa_enlil_57671.77346046.dbqs01/pv-ready-data-57671 s3://h3lioviz.bryandev.swx-trec.com/data/h3lioviz/pv-ready-data-57671`|
# Getting the New Run Populated into Dynamo DB
| Instructions | Commands | Example |
|---|---|---|
|With AWS credentials for the account that holds the run bucket, invoke the sync metadata Lambda deployed by swxtrec-cdk. This will add any runs found in S3 (a run is found by its `data/h3lioviz/pv-ready-data-<run_id>/metadata.json`, which `process_output.py` writes into the run folder) that haven't had their metadata populated into the Dynamo DB table and will also remove any entries in Dynamo DB that do not have an associated metadata.json in S3. The CLI waits only 60 s by default and the sync can run up to 360 s, hence `--cli-read-timeout 400`; `<region>` is the region the stack is deployed in (us-east-1 for SWx-TREC). (The `/h3lioviz/metadata/syncMetadata` route on the paraview ec2 cannot do this: the deployed container has no TABLE_NAME and the ec2 role has no Dynamo DB access.)|`aws lambda invoke --cli-read-timeout 400 --region <region> --function-name h3liovizSyncMetadata-LambdaConstruct out.json`|
|`out.json` should contain `null`. An error message there means the sync failed. Errors for a single run are only written to the Lambda's CloudWatch log, so `null` does not guarantee every run was added.|
|(Optional) Validate that all the runs in S3 that have a metadata.json file have entries in the dynamodb table and vice versa|
|The run should now be available in the ParaView web application upon refreshing the page|
